# Controlled comparison protocol — NOT EXECUTED against real models

The experiment has not been run. Availability of a Claude executable on the host is not permission to import personal credentials or use global memories. This audit excluded real account use, paid additional services and real global configuration. The isolated homes have no authenticated construction model. Loopback listening and registry DNS also failed in the active runtime. No Claude-vs-Codex comparison substitutes for the missing trial.

## Conditions and allocation

- A: Claude Code without the kit.
- B: identical Claude Code version and exact construction model, with the audited full kit.
- C (optional): same kit with Supervisor explicitly disabled as an EXPERIMENTAL CONDITION in its own disposable configuration; never disable production protection in a real project. This condition isolates the marginal Supervisor effect.
- Use new physical copies of `starter/` for each condition and run; initial bytes verified against `manifest.json`. Randomize A/B order and task variations, retain seed, aim for at least three paired runs if existing authorized budget permits. A single run is exploratory.
- Same tools, sandbox permissions, project path shape, budgets, evaluator, task prompt and time cap. No agent may access another condition's files, transcripts, memory, tests or output. Same external dependency probe behavior. Separate HOME, XDG, CLI sessions and scoped temporary model configuration; verify every symlink.
- Specify model/version, approval policy, permitted local writes and access before any run. If the full kit forces different construction models/tool capabilities, report the confound; don't call the result a clean kit-only effect.
- User gate decisions for the benchmark must be explicitly identified as simulated or truly supplied by the owner. Never infer approvals from the task, stored memory or elapsed time. G4/deployment remains out of scope.

## Frozen task and independent evaluation

Give both builders `TASK.md`, `starter/tasks.py`, and the harmless `dependency_probe.py`. Freeze acceptance criteria before runs; withhold `evaluator/` from both builders. Run the evaluator afterward from the auditor's workspace against each output. It uses only standard-library Python and isolated data paths. Tests measure 12 functional properties, with six current starter successes and six intentionally missing/defective properties. This 6/12 starter measurement is oracle characterization, NOT a kit score or productivity effect.

The bundle includes a new feature (status filter), bug investigation (completed count + meaningful builder regression test), compatible evolution (CSV export), and a transient tool outage (exit75 then exit0, both visibly simulated). An independent maintainer examines the final diff, duplication, interfaces, errors and tests using the same rubric without knowledge of condition. Don't grade by files generated or role count.

## Measurement record per condition and repeat

Copy `metrics-template.json` and fill only observable values:

- Independent acceptance numerator/denominator and failed criteria; existing behavior regressions separately.
- Gate interactions G1/G2/G3/G4 separate from unplanned troubleshooting interventions; don't penalize required gates as autonomy failures.
- End-to-end wall clock, active model time if available, waiting-for-human time separately.
- Tool calls, failed calls, iterations, repair loops and invocations by role. Do not infer these from prose.
- Report actual token/cost counters exposed by runtimes and Supervisor; use null when not available, not zero. Include Supervisor and all agent costs in B.
- Version/hash of final delivered candidate, evidence paths and whether independently verified.
